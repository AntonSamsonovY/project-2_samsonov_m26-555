# Примитивная база данных

Учебный проект №2: консольная база данных на Python. Программа позволяет
создавать таблицы, добавлять, выбирать, изменять и удалять записи. Структура
таблиц и данные сохраняются в JSON и доступны после перезапуска приложения.

Автор: Антон Самсонов, группа М26-555.

## Установка и запуск

Требуются Python 3.12 или новее, Git и установленный `uv`.

```bash
git clone https://github.com/AntonSamsonovY/project-2_samsonov_m26-555.git
cd project-2_samsonov_m26-555
uv sync
uv run project
```

`uv sync` создаёт окружение `.venv` и устанавливает зависимости из `uv.lock`.
Вручную активировать окружение для команд `uv run` не требуется.

Команды базы вводятся после приглашения `Введите команду:`, а не в системном
терминале. Для завершения работы используйте `exit`.

## Команды

| Команда | Назначение |
| --- | --- |
| `create_table <имя> <колонка:тип> ...` | Создать таблицу |
| `list_tables` | Показать названия таблиц |
| `drop_table <имя>` | Удалить таблицу и файл её записей после подтверждения |
| `insert into <имя> values (...)` | Добавить запись |
| `select from <имя>` | Показать все записи |
| `select from <имя> where <колонка> = <значение>` | Выбрать записи по условию |
| `update <имя> set <колонка> = <значение> where <колонка> = <значение>` | Изменить записи по условию |
| `delete from <имя> where <колонка> = <значение>` | Удалить записи по условию после подтверждения |
| `info <имя>` | Показать колонки и количество записей |
| `help` | Показать справку |
| `exit` | Выйти из программы |

Команды и ключевые слова вводятся в нижнем регистре. Имена таблиц и колонок
должны быть допустимыми идентификаторами Python; регистр имён учитывается.

### Типы и ограничения

- Поддерживаются `int`, `str` и `bool`; значения проверяются строго по типу.
- Строки заключаются в двойные кавычки, логические значения записываются
  как `true` и `false`.
- Колонка `ID:int` создаётся автоматически. При вставке ID указывать не нужно,
  а изменять его нельзя.
- Значения при вставке перечисляются в порядке колонок, заданном при создании.
- Новый ID равен максимальному ID среди текущих записей плюс один. После
  удаления записи с максимальным ID её номер может использоваться повторно.
- Условия поддерживают одно сравнение на равенство. Команда `update` изменяет
  одну колонку и затрагивает все записи, соответствующие условию.
- `update` и `delete` требуют условие `where`.
- Для подтверждения удаления введите `y`. Любой другой ответ отменяет действие.

## Пример полного цикла

Запустите `uv run project`, затем вводите следующие команды по одной.
Сценарий создаёт и удаляет только учебную таблицу `demo_users`. Перед запуском
убедитесь через `list_tables`, что таблицы с таким именем ещё нет.

```text
create_table demo_users name:str age:int active:bool
list_tables
insert into demo_users values ("Антон", 29, true)
insert into demo_users values ("Иван", 30, false)
select from demo_users
select from demo_users
select from demo_users where active = true
update demo_users set age = 31 where name = "Антон"
select from demo_users where name = "Антон"
info demo_users
delete from demo_users where name = "Иван"
n
select from demo_users
delete from demo_users where name = "Иван"
y
select from demo_users
drop_table demo_users
y
list_tables
exit
```

При повторной одинаковой выборке появляется сообщение
`Результат получен из кеша.` После изменения записей или структуры таблиц кеш
очищается. Результаты ошибок не кешируются, а пустые выборки кешируются.

Для проверки ошибок можно создать отдельную таблицу и выполнить:

```text
create_table demo_errors age:int
insert into demo_errors values ("тридцать")
select from demo_errors where age = true
update demo_errors set ID = 10 where ID = 1
delete from demo_errors
drop_table demo_errors
y
```

Первые четыре команды после создания таблицы выводят ошибки: неверный тип
вставки, неверный тип условия, запрет изменения ID и отсутствие `where`.

## Хранение данных

- `db_meta.json` — названия таблиц и описания колонок.
- `data/<имя_таблицы>.json` — записи соответствующей таблицы.
- Отсутствующие файлы загружаются как пустые структуры.
- Файлы данных создаются относительно текущего рабочего каталога. Для работы
  с одной и той же базой запускайте приложение из одного каталога.
- Данные, виртуальное окружение и служебные кеши исключены из Git.

Удаление таблицы после подтверждения удаляет её JSON-файл без возможности
восстановления средствами приложения. При необходимости заранее сохраните
резервную копию.

Кеш хранится только в памяти текущего процесса. Одновременная работа нескольких
процессов с одной базой и внешнее редактирование JSON во время работы программы
не поддерживаются.

## Структура проекта

```text
src/primitive_db/
├── __init__.py
├── main.py        # Точка входа консольной команды
├── engine.py      # Ввод команд, проверки и табличный вывод
├── core.py        # Операции над таблицами и записями
├── parser.py      # Разбор значений, условий и изменений
├── utils.py       # Чтение, сохранение и удаление JSON-файлов
├── decorators.py  # Обработка ошибок, подтверждение, время и кеш
└── constants.py   # Пути хранения и поддерживаемые типы
```

Используемые зависимости: `prompt` для ввода команд и `prettytable` для вывода
таблиц. Окружение и зависимости управляются через `uv`, качество кода проверяется
Ruff.

В `decorators.py` реализованы:

- `handle_db_errors` — обработка ошибок операций базы с возвратом `None`.
- `confirm_action` — фабрика декораторов подтверждения удаления.
- `log_time` — замер времени `insert` и `select` через `time.monotonic()`.
- `create_cacher` — замыкание со словарём результатов выборки и очисткой кеша.

## Проверка качества и сборка

Следующие команды выполняются в системном терминале из каталога проекта,
после выхода из приложения:

```bash
uv run ruff check .
uv run ruff format --check .
uv build
uvx twine check dist/*
```

Последняя команда проверяет собранные пакеты, но не публикует их.
